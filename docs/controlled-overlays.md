# Controlled overlay and draft retirement

`/?overlays=1` reuses PlaybackStartup and the existing reviewed plugin/runtime/catalog/CSS paths. Actual published design-components0.4.0 FormDialog, ConfirmDialog, OverflowMenu, Input and Textarea render transient app-owned draft state. No shared API, dependency, candidate or business executor was added. Previews and discard outcomes affect local presentation only; there is no save, authentication, provider effect or persistence.

The app fixture uses unchanged finite presentation-session tickets with explicit preview/discard channels. Its identity includes frame context/source/epoch plus the actual admitted Detail view's hostInstance, durable ID and generation; availability also requires runtime.isCurrent. Durable IDs intentionally exclude generation, so owner generation must be tracked separately. All captured callbacks and held commits re-read current scope. Draft changes, close, owner withdrawal, generation replacement, source/frame/context retirement and disposal cancel prior authority. Producers intentionally ignore AbortSignal until the explicit release control, but cannot commit retired results. The previous context's release callback is retained for actual late-completion proof; this does not imply backend cancellation or rollback.

FormDialog disables its submit button but does not independently guard native form submission. The app callback checks nonempty draft, current scope, open state and busy state before enqueueing. Busy Escape/close is treated as cancellation for both FormDialog and ConfirmDialog. Rejected and accepted previews retain the draft; accepted local discard clears only that transient draft. Stale captured callbacks cannot enqueue fresh work after draft or scope retirement.

Normal close restores the surviving originating control: the direct form button or the overflow menu trigger, never a detached menu item. Ownership/source retirement routes focus to the surviving current host heading. Each focus animation frame captures its target node and identity, cancels on lifecycle changes, and checks mounted/current ownership before focusing. Pending retirement focus survives the brief unavailable-to-new-generation transition. Context replacement and unmount dispose the old fixture and focus the replacement or retired consumer heading; old callbacks cannot steal that focus.

The isolated Go fixture offers one additional read-only registry with reviewed fake-ops g2 bytes and monotonically newer revision. Delivery paths remain generation-bound; stable-plugin remains g1. Same-ID replacement closes the overlay, removes the old style lease and installs exactly one new generation lease while unrelated widget state survives. This is local fixture delivery, not upstream adoption or a mutable configuration endpoint. Playback's existing source-frame remount policy remains explicit.

Three unit cases and nine Chromium cases cover invalid/busy native submit, ignored-abort producer fencing without subscription notification, stale callbacks, rejected/accepted outcomes, actual keyboard menu navigation/disabled item, dialog focus containment and origin restoration, busy Escape, source/owner/generation/context/unmount retirement, exact stylesheet ownership, narrow native field readability and no external/mutation requests. Desktop and narrow captures use actual viewport dimensions. The narrow proof checks all dialog bounds, a bounded scrolling form body, reachable sticky footer and focused fields. Existing Go/frontend/frame/admin/observation/developer/voice/shell/playback/dashboard regressions remain required.

Main-origin is still the explicit reviewed offline fixture choice; opaque verified-frame behavior is unchanged. Folio0109 remains backlog; no Folio/Tachyon source, upstream library, npm publication or deployment is included.
