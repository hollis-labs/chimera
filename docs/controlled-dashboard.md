# Controlled dashboard composition

`/?dashboard=1` adds a bounded dashboard branch to the existing playback consumer. Released `@hollis-labs/kit-dashboard@0.4.0` Panel, KpiGrid, Kpi and BarList render app-owned props. It reuses the exact PlaybackStartup lifecycle, registry, catalog, layout store, stylesheet leases and shared dispatcher; no host API, dashboard framework or dependency was added.

Counts refer to recorded authored events through the displayed UTC cutoff in the current source. Before the final boundary, coverage is labelled **partial recorded prefix**; the final boundary is the complete authored fixture. Observed errors are an explicit authored zero. Spend is null/uncollected with no currency evidence. Category bars count one event each from the same visible prefix. There is no fabricated rate, rolling trend, receipt timestamp, live freshness or provider measurement. The cutoff label is “Evidence through,” not a receipt claim. The existing immutable frame drives actual plugin render props and invocation together.

Composition controls change local compact/expanded placement or the existing summary region order/visibility without restamping the frame. The stable-plugin widget retains its count, fake-ops Detail panel retains its count, and the separate operations.toolbar held action stays current through those changes. Hiding only fake-ops summary deliberately unmounts that widget; restoring it resets its own local count. Reordering retains keyed widget parents. A frame/source change intentionally remounts transient plugin presentation and fences the previous producer. Context replacement disposes the old host. Withdrawing fake-ops removes its views and generation stylesheet while the unrelated stable-plugin widget and embedded dashboard evidence survive.

The proof inherits explicit reviewed offline main-origin policy; verified-frame delivery remains unchanged. Held producers ignore AbortSignal until explicit release, and the existing shared dispatcher/session fences prevent retired outcomes from updating current receipts or component text. No backend cancellation or rollback is claimed.

Released dashboard widgets use legacy text/panel utility names. The demo app maps those names to current semantic fg/fg-muted/bg-elevated/surface tokens; it does not edit package CSS or runtime. Browser checks compare rendered primary/muted text to actual theme colors, require opaque panel/bar backgrounds, verify compact grid columns and reordered widget DOM, and check narrow keyboard focus, no horizontal overflow and a single document scroll owner.

One unit case checks all four cutoff projections, count totals, zero versus null, future outcome withholding and source reset. Four Chromium cases cover actual dashboard composition, retained hooks and held action authority, source/context/owner retirement, style cleanup, narrow keyboard/token rendering and no external/mutation requests. Full existing Go, frontend, verified-frame, administration, observation, developer, voice, shell and playback regressions remain required. No business/provider/backend effects, persistence, upstream Folio/Tachyon adoption, npm publication or deployment is included.
