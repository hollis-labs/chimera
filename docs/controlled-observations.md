# Controlled observation integration

Use the released `kit-observe@0.1.1` root components and their actual `ObservationState`, `HealthSummaryProps`, `StatCollectionProps` and `DiagnosticPanelProps`. Opt into `SampleSeriesView` and `SampleSeriesViewProps` from `/charts` explicitly, with the published `kit-dashboard@0.4.0` peer installed. Chimera's fixture pins that peer directly; no existing package versions or frame candidate bytes changed. The library fixture imports chart types only; it does not pull a chart implementation into the adapter root. The example consumer deliberately opts into the chart renderer.

`controlledObservationFixture(contextKey, nowMs, sourceKey)` is an app-owned example, composed exclusively of those kit projections. Its public state is a presentation snapshot, not a telemetry wire schema or transport. The application owns authorization, manifest/source identity, wire validation/sanitization, declared units, resource bounds, successful receipt provenance and retained payloads. No generic resolver, polling schedule, validator or chart engine is introduced.

The existing unchanged `createAdminPresentationSession` supplies finite resource channels. A refresh starts a new ticket for only that resource and labels its retained snapshot loading. Its old value and `observedAt` remain intact. `releaseNext()` completes a deliberately held scripted producer that ignores abort; the actual local commit executes only through the ticket. A failure labels the same retained evidence with a resource-local error and preserves the last successful timestamp. Success stamps the controlled receipt time; it never means healthy. Source/context retirement resets app-owned state and fences old producers. Same-channel supersession does not cancel sibling resources. Disposal is terminal. These signals do not imply backend operations were cancelled or rolled back.

The clock is explicit, with no timer or request on clock changes. Every resource receives the current controlled `nowMs`; old success times and exact sample timestamps are never restamped by ticking. A skewed clock remains visibly unavailable rather than being clamped or interpreted as fresh. Source retirement creates a new explicitly scripted fixture snapshot, not a claim of a backend reread. Real consumers must supply their own validated authorized evidence.

The authored baseline deliberately distinguishes unknown health, a real zero cumulative count, a missing/null bytes sample, a ratio of 0.5 and a percent value 50. Resource-local ages differ; there is no sibling success/timestamp reuse. The exact four-point series is `[0, null, 2, 1]`, preserving a null gap and counter reset rather than inventing a rate. Points are ordered unique UTC instants in a declared three-second window, capped at four points. Every sample is at or before its successful receipt, which is at or before the baseline clock. The actual shared chart and accessible UTC table preserve those exact values and timestamps. No sorting, resampling, unit conversion or manufactured history occurs here.

Diagnostics are a small explicitly authored bounded object and matching inline schema, with an app-supplied validation result. Invalid/unsupported scenarios withhold the payload and copy control; retained refresh failure preserves valid evidence and its original timestamp. Initial loading/error scenarios omit successful timestamps, so all components withhold their provisional fixture values. Unsupported, empty, truncated and paused series states remain distinct; none silently become a healthy result or zero sample.

The isolated consumer at `/?observations=1` renders the actual root/chart components in a token grid with one document scroll. Browser proof covers per-resource initial/refresh/failure states; health/stat/series/diagnostic retained evidence; context/source/latest-request producer fencing; exact UTC table and bounds; counter/ratio/percent semantics; fixed-clock stale/skew labels; accessible schema keyboard details; and narrow layout/style. Chart size follows its actual 192px token class, table cell padding is 8px, and the document stays within 390px after the chart owner's ResizeObserver settles. Live screen-reader speech, other browsers, telemetry services and provider/business effects are not claimed.

Only app-owned fixtures and proof were added in Chimera. Parallax owns its logs/traces review surface, filters, scrub selection and domain snapshots. Folio/Tachyon adoption remains outside this checkpoint, and Folio0109 stays backlog. No npm publication, service deployment or upstream repository changes occurred.
