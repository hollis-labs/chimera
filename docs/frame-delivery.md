# Verified frame delivery

Chimera integrates the pinned shared `plugin-host-ui/isolation` importer/controller. It does not define a sandbox protocol, registry, loader, action dispatcher or manifest format. The existing MIT candidate remains byte-identical: design-kit `dbcf4fa7f5bcfe83686d227b39ddf9426cea4fe5`, archive SHA-256 `360c4bd74df7369d57af74151bba0ff0739b31b5c67499f1c01c15cefb4b24b0`.

`createIsolatedComposition` creates one `createPluginFrameBrowser` and passes its verified importer into the existing registry and that same controller into the host runtime. Current contribution checks use the exact registry kind/key/owner/generation/host-instance lease. The application supplies `review`, approved runtime artifacts and requested exports, complete effective-mode store, schema/allowlist props projection, compiled per-view bindings and explicit main-origin authorization. Component bindings resolve through the shared `dispatchBoundAction` gateway and the same application action policy as parent-rendered contributions. Disposal releases registry/controller subscriptions synchronously, including constructor failure; there is no deferred observer attachment.

## Exact artifacts and document policy

`frontend/example/frame-build.ts` uses the existing shared `buildFrameArtifacts` and `buildFrameBootstrap`. Its closed inventory contains pinned React 19.3.0, React DOM 19.3.0 (`react-dom` and `react-dom/client`), JSX runtime, and design-components 0.4.0 Button. Compiled token/component CSS is included as a verified style artifact. The shared builder refuses unexpected module imports, non-CSS assets, unbundled graphs and network CSS. Exact bytes and SHA-256 digests travel to each realm; the shared importer verifies the plugin digest again and never executes a later fetch from the source URL. Each surface initializes independently after a separate opaque export-verification realm has retired. Frozen inert handles are not callable parent components.

The build also calls upstream `createFrameDocument` to emit the exact bootstrap HTML/CSP/Permissions-Policy template. Only its cryptographic frame/bridge/document nonce and parent-origin positions become substitution tokens. This preserves the upstream fixed bootstrap hash, importmap nonce policy and permissions string. No parent CSP is relaxed. The frame uses `sandbox="allow-scripts"`, an opaque origin, no-referrer and the upstream restricted permission allowlist.

Go `host.NewFrameDocuments` is an optional app-mounted bounded transport for admitted immutable documents. It installs no routes itself and requires an admission callback. The callback must establish exact reviewed HTML/CSP/Permissions-Policy and request authority. Documents cannot overwrite an existing frame ID; defaults are 128 retained documents, a 2 MiB request bound and five-minute lifetime. Expiration is checked on access/provisioning; retention is always capacity-bounded. `Clear` releases retained bytes. GET snapshots before network writes and serves exact CSP and Permissions-Policy response headers, matching CSP meta policy, no-store and no-referrer. Deleting a URL does not recall already executed code; the browser controller separately revokes the realm/ports/lease.

The isolated fake consumer mounts `/api/frame-documents/`. Its callback admits only exact upstream-template substitutions, canonical 32-byte base64 document nonces, lowercase hexadecimal bridge/frame nonces and the explicitly reviewed loopback parent origins `http://127.0.0.1:18543` / `http://127.0.0.1:18544`. POST and DELETE require one of those Origin headers; POST additionally requires the document's parent origin to match that request. Arbitrary HTML, relaxed policies, changed bootstrap bytes, foreign origins and unsupported fields are refused. These loopback origins are fixture policy, not production defaults. There is no document route without the reviewed build artifact.

`httpFrameDelivery` posts that exact shared document to an explicitly assured same-origin endpoint, refuses redirects/failure, returns its dedicated frame URL and releases it once on revocation. Provisioning/cleanup requests have bounded timeouts; unavailable policy remains named and visible. `policyAdmitted: true` is the consumer's assurance that its endpoint serves the exact policy; it is not browser-policy introspection. An application with restrictive inherited CSP must independently admit compatible dedicated-frame policy or refuse. The adapter never relaxes inherited policy or falls back to main-origin.

## App integration choices

Create one instance per application/context and dispose it when that context retires. Declare approved runtime versions and frame variants before reviewing bundle owner/generation/digest/export tuples. Supply JSON props containing only schema-approved presentation context; credentials, service handles and provider configuration do not enter frames. Return bindings only for the current reviewed component sources and resolve their exact descriptors through the shared action binding resolver. Keep application grants, target/argument validation and effects in the application adapter.

The pinned React adapter treats forwarded props updates as context replacement and cancels active frame calls. The example memoizes the surface subtree separately from receipt/navigation observers so ordinary inspector changes do not churn props; real render-context changes still update props and abort pending producers. Application integrations should preserve that distinction. The package's shared registry also permanently revokes a generation after failed activation: do not retry that generation. The example's denied main-origin g2 never executes in the parent; explicitly authorized fresh g3 may execute and reports `main-origin-ambient-authority`. Changing mode fences opaque realms first. Previously executed main-origin code has ambient authority and cannot be recalled; cooperative parent views must be unmounted before mode changes.

`/?frames=1` demonstrates the reviewed frame consumer on port 18543. Routes, modal and handler names are fixture application policy. Commands create only labelled transient simulation receipts; they execute no provider/business operation. Delayed producers deliberately ignore cancellation at the playback gate, while signal/epoch checks prevent late receipts after source/target/scope/invocation/caller/context/generation retirement. The frame bridge reports `unknown-outcome` after its execution boundary; that is an interruption receipt, not evidence of a committed business effect, and it must not cause automatic retry.

## Validation and limits

`npm run test:browser` exercises actual Go document delivery: exact HTML/CSP/Permissions-Policy, unauthorized POST/DELETE and forged policy refusal, React/design/style artifacts, opaque DOM/storage/cookie denial, independent counters, sibling disposal, owner/generation replacement and document release, shared typed navigation/modal, denied/undeclared actions, delayed producer fences, context updates, explicit mode authorization and failed-policy refusal with no fallback. The browser matrix also checks blocked fetch/subresources/forms/popups/top-navigation against server ingress observations. Browser instrumentation may emit a request event for a CSP-blocked image; the server counter is the delivery evidence.

`npm run test:upstream-frames` runs MIT upstream browser acceptance sources copied from the exact candidate source commit. Adaptations are installed-package imports, package/client paths and repo-local scratch. Assertions are unchanged; the test-only port instrumentation never ships in the application. It covers fifteen documented mechanism groups including forged exports, bootstrap source/origin/nonce/version/schema/port admission, replay, cancellation/uncertainty, cleanup failure, focus, mode/singleton behavior and self-navigation. See `frontend/upstream-frame-browser/README.md` and its preserved LICENSE.

Self-navigation can send a request before the host observes navigation and revokes the session. Both the upstream harness and actual Go-served frame test observe that egress, then verify a failed session while a sibling remains usable. No universal browser egress prevention, CPU/memory containment, provenance, signature verification, manifest permissions or host grant validity is asserted. Unsigned reviewed fixtures report `unsigned`. Results apply to the tested Chromium and these reviewed delivery/runtime choices; other browsers, runtime inventories and inherited policies need their own application verification.

Folio adoption and Tachyon migration remain outside this repo's delivery. No shared checkout, provider, managed service or live preview was modified; no npm package was published.
