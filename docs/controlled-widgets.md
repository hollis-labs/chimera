# Controlled compact widgets

`/?widgets=1` uses the existing PlaybackStartup host and pinned kit-dashboard0.4.0/widgets Sparkbars, SignalBars, DonutChart, MiniTrend and RecentList, plus design-components0.4.0 Metric. These are actual published renderers; there is no new host API, graph/chart engine, wire schema, dependency or ambient clock.

The application authors four fixed UTC boundaries and finite, nonnegative primary `[0,2,1,3]` / secondary `[0,1,0,2]` count samples. Both share the same unit and boundary array; only the prefix at the current review cutoff is passed. These counts are independent authored signals, not derived event rates or upstream receipts. The accessible table supplies the values hidden by Sparkbars/SignalBars paint. MiniTrend's displayed cumulative count is the sum of that same current primary prefix.

SignalBars clamps its built-in peak scale to at least one and paints two columns per bucket. The wrapper separately labels the actual observed peak (including zero) and explains both behaviors. Square-cell paint widths are bounded using the spacing token so all six Sparkbars rows and eighteen SignalBars rows fit their authored height; tests verify cell bounds and paired column values. Narrow legends retain both same-unit sums. The fixture does not pass null into number arrays or compress missing buckets into fabricated continuity.

DonutChart receives only the current record-class denominator: nonterminal versus terminal authored rows. Terminal classification appears only at the final boundary. Its legend and rounded percentages are supplied by the actual component; the application does not claim a controlled chart-legend API. A separate known-zero sample retains the renderer's generic “No data recorded” wording with an explicit observed-zero explanation. Spend remains null/uncollected, distinct from observed errors zero. The empty RecentList explicitly labels unavailable/uncollected records. These widgets are illustrative authored evidence, not operational telemetry.

Local secondary-signal visibility, compact layout and RecentList selection use a private fixture controller. Captured callbacks re-read the actual admitted Detail contribution before accepting changes: context, source, frame epoch, host instance, durable ID, generation and runtime currentness. Same-ID g2 replacement, owner withdrawal, source/context replacement, seek/reset and unmount retire local state and captured callbacks. Scope policy remains app-owned; the shared registry/host remains authority. Normal layout/signal changes retain the selected record. Source/frame changes follow PlaybackStartup's intentional presentation remount policy; owner/generation changes preserve unaffected stable-owner hooks while the old owner stylesheet is revoked. No widget-hook retention across playback frame remount is claimed.

Two additional unit cases verify authored prefix truthfulness and private callback fencing (typed currentness stubs). Seven Chromium cases use actual admitted plugin/registry delivery, generation-bound g2 bytes, paired signal paint, donut ratios, current tokens, keyboard selection, narrow overflow, retirement/style leases and backward seek/reset. Desktop/narrow full-document captures include host context and plugin presentation; separate 1280×720 and 390×844 scrolled viewport captures demonstrate the normal three-column layout and narrow signal panel. Full-document captures are not viewport-fit claims.

There is no code/workflow/business execution, provider/network service, persistence, clipboard/download, upstream write, npm publication or deployment.
