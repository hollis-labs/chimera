# Controlled evidence inspector

`/?inspector=1` composes published design-components0.4.0 JsonViewer, PayloadSummary, MetaList and SearchInput with the existing DetailDialog. JsonModal and PayloadActions always render clipboard actions and expose no supported omission flag, so neither is adopted or disguised here. There is no copy, download, business/provider effect or new shared host API/dependency.

The app owns four bounded authored record boundaries inherited from PlaybackStartup. Only records at or before the displayed cutoff are projected. Payloads preserve authored error zero versus spend null/uncollected; timestamps are authored `recordedAt` values, not upstream receipts. Final outcome fields appear only on the terminal record. One explicitly labelled malformed raw fixture is rendered as a literal string diagnostic; the actual JsonViewer is used for both pretty JSON and that literal. PayloadSummary is bounded to four entries and its scalar spans are constrained by consumer CSS; full authored content remains accessible in the selected inspector. Metadata labels the source, generation, cutoff and partial/complete fixture coverage.

Search, selected payload and modal state are app-owned. Their scope reads the actual admitted Detail view: context/source/frame epoch, ref.hostInstance, durable view ID, ref.generation and runtime.isCurrent. Durable IDs deliberately exclude generation, so same-ID g2 replacement retires the old local state. Captured callback leases re-read current scope before accepting a deferred search result; selection/modal changes also retire older callbacks. SearchInput remounts at those boundaries to cancel its internal debounce, while ordinary committed query updates preserve typing focus. Its global slash shortcut is disabled while a modal is open or ownership unavailable. No telemetry transport, payload validator or parallel renderer is introduced.

Owner/generation/source/context retirement clears search and selection and closes the modal. Generation replacement uses the existing reviewed generation-bound g2 fixture delivery; the stable owner retains its hooks. Source-frame changes follow PlaybackStartup's documented presentation remount policy while retaining registry/CSS. Owner replacement/withdrawal releases the old generation stylesheet without removing host styles; context replacement and unmount dispose the old consumer.

Normal close restores the surviving selected-payload trigger. Retirement focuses the current host heading. Focus RAF callbacks capture the node, current scope and control epoch, cancel on lifetime changes, and verify closed state before applying focus. A fresh same-frame reopen clears pending origin focus so an old close cannot move focus behind the new dialog. Pending retirement heading focus survives unavailable-to-new-generation transitions. Unmounted callbacks cannot steal replacement focus.

Three unit cases cover authored projection, zero/null/future withholding, raw literal classification and private controller callback retirement. The controller units isolate currentness with typed fixture stubs; nine Chromium cases exercise the actual admitted runtime/catalog/registry path, same-ID generation replacement, stable-owner/style survival, source/context/owner/unmount retirement, real search slash/Escape and debounce behavior, dialog Tab/Escape focus and same-frame reopen. Narrow checks prove viewport bounds, reachable final lifecycle control through the bounded dialog body, sticky footer, JSON horizontal scrolling to the final characters without page overflow and no external/mutation requests.

The closed desktop screenshot is a full document capture. Separate desktop and narrow modal captures use actual 1280×720 and 390×844 viewports; no document-height image is claimed as viewport-fit evidence. All existing Go, frontend, opaque-frame, action, administration, observation, developer, voice, shell, playback, dashboard and overlay gates remain required. Main-origin remains the explicit reviewed offline fixture choice. Folio0109 stays backlog; no upstream edit, provider execution, npm publication or deployment is included.
